# r6d 标定记录：演习次数（jjc_times）字模与几何

日期 2026-11-13。所有数字都是**真机帧量出来的**，不是估的。

## 几何（最终值）

| 项 | 值 | 怎么来的 |
|---|---|---|
| 文本区域 | `region = [2000, 213, 76, 34]` | 列投影扫 219 帧，右沿恒在 2076；左界取 2000 是为了容纳 `10/10` 最左边那个被截断的 `1` |
| 字形高度 | 34（模板高，字实际高 24） | 带内上下留白一并切进模板，匹配时窗口同高 |
| 布局 | `right_to_left` | 右边界恒定，位数可变 |
| 默认字距 | `cell_step = 12` | 仅作为 `advance` 缺省值 |
| 阈值 | `0.90` | 不放宽 |

## 🔴 关键修正：字距**不是**固定 12，是逐字符 advance

早先记录写「字距 12px」，按固定 12 步进实测**必然错位**，`10/10` 会读成 `0/10`。

从多帧右沿差值实测（`10/10` 与 `X/10` 两种长度交叉验证一致）：

| 字符 | advance |
|---|---|
| `0` | 16 |
| `1` | 11 |
| `/` | 12 |
| 其它数字 | 12（**未直接实测**，只验证过它出现在最左位、不影响读数） |

写进 `reads.json` 的 `advance` 字段；代码里 `cursor -= advances[char] ?: cellStep`。

## 另一个坑：`/` 不能直接当文件名

`loadTemplate` 原来拼 `digits/$field/$char.png`，字符 `/` 会变成路径分隔符 →
`digits/jjc_times//.png`，模板必然读不到。现在非字母数字字符统一映射成 `slash.png`。

## 字模来源

素材来自 2026-11-13 那轮演习（10 场打满，次数 10→0 全程覆盖）。
真值不靠视觉模型，靠 **`jjc_run.log` 的「次数复核：X → Y」行 + 帧名 HHMMSS 对齐**：

```
09:26:57 起 10/10 → 09:29:12 10→9 → 09:32:34 9→8 → 09:34:57 8→7 → 09:37:12 7→6
→ 09:39:27 6→5 → 09:41:42 5→4 → 09:44:46 4→3 → 09:47:00 3→2 → 09:49:13 2→1 → 09:51:31 1→0
```

注意：日志行记的是**结算之后**的次数，而收尾帧比日志行早 3~5 秒（脚本先截图后打日志），
所以对齐时锚点要**整体提前 20 秒**，否则整条序列错一档。

生成脚本：`~/.hermes/data/azurlane/gen_digits.py`（切分）+ `gen_digits_build.py`（标注入库）。
产物：`assets/digits/jjc_times/{0..9,slash}.png`，11 张，高 34，宽 10~15。

（`score = 1 - SAD / (255 × w × h)`）在同一批真机帧上跑：

**31/31 命中**，覆盖 11-10、11-12、11-13 三轮、次数 10→0 全部档位。
其中 6 张 `10/10` 是专门用来验「左边界裁切 + 最左 `1`」的。
