## 二、要测的四组

### 第 1 组：取帧（地基）

| 编号 | 测什么 | 判定 | 及格线 |
|---|---|---|---|
| F-1 | 连续取 100 帧 | 记录每帧耗时 | 中位 < 50ms，P99 < 200ms |
| F-2 | 帧序号连续 | 有无丢帧、重复 | 100 帧无丢无重 |
| F-3 | 帧内容正确 | 抽查 5 帧与真机画面一致 | 全部一致 |
| F-4 | 长时间稳定性 | 连续取 500 帧 | 无内存增长（±20MB 内）、无崩溃 |

### 第 2 组：找图（判页核心）

| 编号 | 测什么 | 判定 | 及格线 |
|---|---|---|---|
| M-1 | 小区域找模板 | 给模板图和搜索范围，返回坐标 | 偏差 < 5px |
| M-2 | 全屏找模板 | 同上但整屏 | 偏差 < 8px |
| M-3 | 同帧重复 50 次 | 结果一致性 | 50 次全同 |
| M-4 | 目标不存在 | 给画面里没有的模板 | 必须返回「未找到」，**不许给坐标** |
| M-5 | 相似干扰 | 用列表页找「开始演习」模板（列表页有相似的橙色按钮） | 必须不误命中 |
| M-6 | 半遮挡/动画中 | 用战斗动画帧找结算按钮 | 允许找不到，但不许给错坐标 |
| M-7 | 多模板同时找 | 一次给 4 个模板，返回各自是否命中 | 全部正确，总耗时 < 100ms |

**M-5 很重要**：之前踩过的坑是「积分结算页右下角也有同款橙色按钮」，判据一松就误点。

### 第 3 组：认数（判数）

| 编号 | 测什么 | 样本 | 及格线 |
|---|---|---|---|
| O-1 | 演习次数「n/10」 | 列表页次数框（25×25 级别） | 准确率 ≥ 95%，错 ≤ 2/40 |
| O-2 | 四张卡战力（主力+先锋） | 列表页战力带 | 与现有 OCR 结果一致率 ≥ 95% |
| O-3 | 竞技场三行战力 | crosscore 的 ar_opp 帧 | 漏读率 ≤ 3%（现在 9%） |
| O-4 | 中文标签 | 「演习对手信息」「主力舰队」 | 准确率 ≥ 90% |
| O-5 | 纯色/空白数字框 | 无数字的画面 | 必须返回「无」，不许猜 0 |

**O-2 的口径**：以现有 `bl_lib.scan_cards()` 多票结果为准，不一致的人工复核。

### 第 4 组：端到端

| 编号 | 场景 | 测什么 | 及格线 |
|---|---|---|---|
| E-1 | 碧蓝一轮 | 列表 → 详情 → 编队 → 结算 → 回列表 | 总耗时对比现状（现状约 6 分钟/轮） |
| E-2 | 碧蓝一轮（仅判页） | 纯判页，不点击 | 每屏 < 300ms |
| E-3 | 交错冷启动 | 判 home / base / staff | 判对率 100%，< 300ms |
| E-4 | 交错竞技场 | 判页 + 读三行 + 选人 | < 1.5s（现状约 3s） |
| E-5 | 交错订单 | 认订单列表 + 读剩余次数 | 判对率 ≥ 95% |

**E-1 是最终数字**，其他都是为它服务。

## 五、硬约束（写进任务书）

1. **不许碰现有脚本**：`~/.hermes/skills/gaming/game-daily-relay/scripts/` 下的所有 py 文件保持原样，改造代码走独立目录 / 独立分支。
2. **不许动线上 relay**：服务端（`~/.hermes/hermes-relay/plugin/`）在跑 QQ 通道，改造只在 fork 仓库进行，不合回、不重启。
3. **不许让手机脚本变慢**：改造期间用户可能随时跑 `#bl-jjc` / `#mh-jy` / `#jc-jd`，任何改动不得影响这些路径。
4. **测试全部离线**：Codex 在 Windows 上跑，没有手机，只吃 `frames/` 里的图。
5. **报告要出数字**：每项测试输出「准确率 / 耗时中位数 / P99」，不许只写「通过」。
