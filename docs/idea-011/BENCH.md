## 一、现状：服务器端识别有多慢

### 碧蓝航线（bl_lib.py，tesseract）

| 动作 | 中位耗时 | 备注 |
|---|---|---|
| 判页：演习列表 | 2.78 s | 判对 |
| 判页：演习详情 | 1.79 s | 判对 |
| 判页：编队 | **8.5 s** | 判成 other，白等 |
| 判页：主界面 | **11.0 s** | 判成 other |
| 判页：章节地图（负样本） | 8.4 s | 判成 other，正确 |
| 判页：列表加载中 | 2.6 s | 判成 list（误判） |
| 判数：演习次数 0/10 | 0.38 s | 局部 OCR，尚可 |
| 判数：四张卡战力 | **7.9 s** | 每张卡多倍率投票 |

> 测试条件：清空 OCR 缓存后跑 3 次取中位。缓存命中时数字会低到几十毫秒，不代表真实。

### 交错战线（jc_lib_v3.py / jc_arena.py，tesseract）

| 动作 | 中位/单次耗时 | 判定结果 |
|---|---|---|
| 判页：冷启动 | 4.25 s | other |
| 判页：基地 | 1.33 s | home ✅ |
| 判页：竞技场对手列表 | 1.50 s | arena ✅ |
| 判页：竞技场准备 | **5.26 s** | other（无判据） |
| 判页：竞技场战斗 | 4.43 s | other |
| 判页：对话弹窗 | 1.41 s | confirm ✅ |
| 判数：三行战力 | 1.48 s | OCR 一次读全 |
| 判数：三行战力（画面无数字） | **4.35 s** | OCR 空 → VL 兜底 → VL 也空 |

**规律**：判得出来的 1.3~1.5 秒，**判不出来的一律 4~5 秒**（要跑完全部 OCR 才放弃）。

战力读数还有个额外成本：OCR 读空会触发 VL 兜底（约 2.8 秒），兜底再失败才停手。所以**画面里没有数字时，一次读数要烧 4.35 秒**。

竞技场准备页没有判据（判成 other），这是现有脚本的一个缺口。

> 测试条件：清空 `_PAGE_CACHE` / `_TEXT_CACHE` 后单次计时。

## 二、目标：端上本地算法能多快

服务器上用 cv2 实测（同样的 2460×1080 图，同一台机器）：

| 做法 | 中位耗时 | 相对现状 |
|---|---|---|
| 全屏彩色模板匹配（100×50 模板） | 191 ms | 比最慢的判页快 44 倍 |
| 同上，转灰度 | 65 ms | |
| 同上，灰度 + 降采样 0.5 | **11.7 ms** | 快 730 倍 |
| 区域搜索（800×400）彩色 | 19 ms | |
| 颜色判据（区域均值差） | **0.14 ms** | 快 6 万倍 |

手机 CPU 比这台服务器弱，按 3~5 倍折算：

| 做法 | 手机预估 |
|---|---|
| 灰度 + 降采样全屏模板 | 35~60 ms |
| 颜色判据 | < 2 ms |
| 区域模板匹配 | 60~100 ms |

**结论：判页从 8~11 秒降到 50 毫秒以内，量级上成立。**

## 三、竞技场为什么 5 场要 8~10 分钟

从 `jc_run.log` 09:11:01 那次完整记录拆解：

```
09:11:01  进竞技场
09:11:11  没有次数框/三行对手 → 点「镜像竞技」重新校验     ← 10 秒
09:11:21  模拟次数读取：5/10                              ← 10 秒
09:11:29  对手战力读取                                     ← 8 秒
09:11:29  挑战力最低 662 → 点对手卡
09:12:00  已按挑战，等战斗结束                             ← 31 秒
09:13:00  画面静止（战斗结束信号）                          ← 60 秒
09:13:31  打完次数 4/10                                    ← 31 秒
09:13:39  下一轮战力读取                                    ← 8 秒
...
09:21:28  打完 5 场
```

单场约 2 分钟，拆开看：

| 环节 | 单场耗时 | 能否压缩 |
|---|---|---|
| 读对手三行战力 | 8 s | ✅ 端上模板/OCR，目标 < 100ms |
| 读剩余次数 | 10 s | ✅ 同上 |
| 战斗等待（画面静止判据） | 60 s | ❌ 游戏本身时长，压不了 |
| 点击后到画面响应 | 20~30 s | ⚠️ 部分可压缩（现在每次点击后都要重新截图判页） |

**理论上限**：单场 120 秒里约 40 秒是识别和等待，端上识别后能压到 5 秒以内，单场从 120 秒降到 85 秒左右，5 场从 10 分钟降到 7 分钟。

真正的收益在看运气：如果某场判不出战力要重试（现在约 9% 概率），端上能立刻重判，不用等 8 秒。

## 四、编队页判页失效（新发现）

3 张编队页帧全部判成 `other`，耗时 8.4~8.7 秒。

现有判据是「主力舰队 + 先锋舰队」两个词同时在整图 OCR 结果里。实测这屏读不到这两个词。

影响：非盲点模式下会停手；盲点模式不判编队页所以没暴露。

修法：加一条「整图 OCR 含『出击』且右下角有橙色主按钮」的判据，或者直接改用模板匹配。
