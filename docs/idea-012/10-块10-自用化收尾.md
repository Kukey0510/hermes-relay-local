# 块 10 · 自用化收尾（包名 / 显示名 / 去调试入口 / 强制白天 / tab 回一级 / 固定签名）

先读 `00-总纲-云端版.md`。基线：块1-9 已合并，Play 版已摘除，只剩 sideload。

> 🔴 本块**不出包**（CI 自己打）。验收 = `assembleDebug` 通过 + 逐条自查。
> 这是自用分支的收尾块，改动都是「让它更像自己的东西，而不是开发版」。

---

## 1. 改包名（安装身份）

**现状**（`app/build.gradle.kts`）：
- `namespace = "com.hermesandroid.relay"` ← **不要动这个**
- `applicationId = "com.axiomlabs.hermesrelay"` ← 改这个

**要改成**：`applicationId = "com.hermesandroid.hermes_relay_script"`

- `namespace` 保持 `com.hermesandroid.relay` 不变 —— 这样 Kotlin 包路径、import、R 类全部不动，改动面只有一行
- 这是 AGP 支持的模式：`namespace` 是编译期概念，`applicationId` 是运行时安装身份
- **注意**：applicationId 变了等于换了一个 App，和旧包不能共存、数据不共享、要重新配对。用户已知情。

## 2. 桌面显示名改成 hermes

现状：`app/src/sideload/res/values*/strings.xml` 里 `app_name` 是 `Hermes Dev` / `Hermes 开发版`（main 源集里是 `Hermes-Relay`，被 sideload 覆盖）。

**要改成**：所有 sideload 源集的 `app_name` 一律 `hermes`（小写，用户指定）。
涉及文件（全都要改）：
`app/src/sideload/res/values/strings.xml`、`values-b+zh+Hans`、`values-de`、`values-es`、`values-ja`、`values-pt+BR`、`values-ru`（以实际存在为准）。

## 3. 去掉 local page detection 的调试按钮

`app/src/main/kotlin/com/hermesandroid/relay/ui/screens/BridgeScreen.kt:577` 附近，有一个 `connectionViewModel?.startLocalVisionProbe(3000L) { line -> ... }` 的调试按钮块。

**只删界面入口**：把这颗按钮（以及只服务于它的局部状态/lambda）删掉。
**不要动**：`localvision/` 包、`assets/pages.json`、`startLocalVisionProbe` 这个 ViewModel 方法本身、任何桥命令。用户明确说「只是去除按钮」。

## 4. 强制白天模式

用户原话：「删掉黑夜模式，默认就是白天就好了，之前说他反人类的一个点就是这个，完全看不清东西」。

要求：
- 默认主题 = 浅色（light），不再是跟随系统
- 即使系统是深色、即使 `themePreference` 是 `auto`，也**渲染浅色**（`Theme.kt:41` 默认值 `"auto"` → 改成 `"light"`，并且 `resolveDark("auto", isSystemInDark = true)` 返回 false）
- 保留用户手动切深色的能力（`themePreference == "dark"` 仍然生效），只把「跟随系统」这条路堵掉

涉及：`app/src/main/kotlin/com/hermesandroid/relay/ui/theme/Theme.kt` 的 `resolveDark` / 默认参数，以及 `AppearanceNightMode.kt` 里处理 auto 的分支。
交付说明里写清：默认值改成了什么、auto 现在等价于什么。

## 5. 底部 tab 点击回一级菜单

现状：点当前所在 tab 时走 `navigate(tab.destination) { launchSingleTop=true; restoreState=true }`，等于恢复上次的栈，所以进了二级页之后点 tab 还是停在二级页。

要求：**点已经在当前 tab 的标签时，回到该 tab 的根页面**（popBackStack 到该 tab 的 destination，不含 inclusive）。
点在别的 tab 时，维持现有行为（保存/恢复该 tab 的栈）。

位置：`ui/AppScaffold.kt` 的 `NavigationBarItem(onClick = { ... })`。

## 6. 固定 debug 签名（关键：以后升级不用卸载）

现状：出包走 `assembleSideloadDebug`，用的是 AGP 自动生成的 `~/.android/debug.keystore`。CI runner 是干净的，每次构建都新生成一把 → **每个包的签名都不同 → 覆盖安装报「签名不一致」**，必须卸载重装，配对也跟着重来。

要求：
1. 生成一把固定的 debug keystore，放进仓库 `app/debug.keystore`
   - alias `androiddebugkey`，密码 `android`，keyalg RSA 2048，validity 10000
   - 用 `/opt/jdk17/bin/keytool` 生成
2. `app/build.gradle.kts` 的 `signingConfigs` 里显式配置 `debug`：
   ```kotlin
   getByName("debug") {
       storeFile = file("debug.keystore")
       storePassword = "android"
       keyAlias = "androiddebugkey"
       keyPassword = "android"
   }
   ```
3. 确认 `candidate` buildType 的 `initWith(release)` 在 release 无 keystore 时回退到 debug 签名，也走这把固定的

自用项目，debug 私钥进私有仓库可接受。交付说明里写明生成的 keystore 指纹（`keytool -list -v` 的 SHA-256），以后好核对。

## 7. 明确不要做

- ❌ 不动 `namespace`、不动 Kotlin 包路径
- ❌ 不动 `localvision/` 包和 `assets/pages.json`
- ❌ 不删 `startLocalVisionProbe` 方法
- ❌ 不改任何 route 字符串
- ❌ 不动 network/ / accessibility/ / bridge/ / data/ 的内部逻辑
- ❌ 不加第三方依赖
- ❌ 不动 versionName / versionCode（出包前由主控改）

## 8. 验收

1. `JAVA_HOME=/opt/jdk17 ANDROID_HOME=/opt/android-sdk ./gradlew assembleDebug` 通过，贴最后 15 行。
2. `./gradlew :app:outputs` 或 `aapt dump badging` 证明 applicationId = `com.hermesandroid.hermes_relay_script`、label = `hermes`（aapt 在 `/opt/android-sdk/build-tools/*/aapt`）。
3. 逐条写清：包名怎么改的、显示名改了哪些文件、调试按钮删了哪几行、auto 现在等价于什么、tab 点击逻辑改成什么、keystore 的 SHA-256 指纹。
4. 贴 `keytool -list -v -keystore app/debug.keystore -storepass android | grep SHA256`。
