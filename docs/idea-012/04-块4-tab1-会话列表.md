# 块 4 · tab1 整页会话列表（抽 `SessionDrawerContent` body 复用，聊天变二级页）

先读 `00-总纲-云端版.md`（环境、硬约束）和 `03-块3-P1-底部导航.md`（块3 已完成：底部 4 tab 已落地）。

**基线**：`feat/ui-redesign` 上已有 `AppScaffold.kt`（骨架 + 4 tab NavigationBar）与 `RelayApp.kt`（795 行）。
tab1 现在直接指向 `Screen.Chat`，本批把它换成**独立会话列表页**，聊天降为二级页。

---

## 1. 本批目标

微信/QQ 形态：**点 tab1 看到全部会话列表 → 点某条进聊天 → 返回键回列表**。

## 2. 必须做

1. **新建 `ui/screens/SessionListScreen.kt`**（tab1 落地页）：
   - 顶部：标题 + 右上角「＋」（新建会话，`testTag="sessionList.new"`）
   - 主体：会话列表（整页，不是抽屉），支持骨架里已有的加载态 / 空态 / 加载更多 / 失败重试
   - 每一行：沿用抽屉里现成的行组件（活动状态、未读、置顶、归档标记都要照旧显示）
   - 点某行：`navController.navigate(Screen.Chat.route(sessionId = <id>))`
   - 补 `testTag`：`sessionList.root` / `sessionList.item` / `sessionList.new`
2. **抽 body 复用，不许复制**：
   - `ui/components/SessionDrawer.kt` 里 `SessionDrawerContent`（2176 行文件，30+ 参数）现在被 `ChatScreen` 用 59 个实参调用。
   - 做法：把「列表主体」抽成新的可复用 composable（如 `SessionListBody`），**抽屉与整页各自渲染同一个 body**，
     抽屉的视觉/交互必须零变化（它还要继续当抽屉用）。
   - 严禁把 2176 行复制一份到新文件。
3. **数据来源**：`ChatViewModel`（`sessions` / `currentSessionId` / `isLoading` / `hasMore` / `isLoadingMore` /
   未读集合 / `activityStates` / pinned / archived 等）。字段名以仓库里现有代码为准，**不许改 viewmodel 内部逻辑**；
   若要暴露新字段，只能是加 getter。
4. **路由接线**：`BottomTab.Chat` 的目标从 `Screen.Chat.route(...)` 改成新的会话列表 route（新增 `Screen.SessionList`），
   并把 `bottomTabForRoute` 映射补上：`Chat` 子页（`chat?…`）仍归属 tab1，列表页本身也归属 tab1。
5. **二级页形态**：进入 `Screen.Chat`（聊天）时**隐藏底部 NavigationBar**（微信形态），
   `RelayStatusStrip` 保持现状显示（本批不动它，挪 tab3 顶部是块5）。
6. 文案走 `strings.xml`；新增 key 只补 `values/` 与 `values-b+zh+Hans/`。

## 3. 明确不要做

- ❌ 不改 `ChatScreen` 的聊天内容/输入框/顶部栏；只允许改它的抽屉调用处（因为 body 被抽走了）
- ❌ 不动 `SessionDrawer` 的视觉与交互（它仍是抽屉，行为零变化）
- ❌ 不改任何现有 route 字符串；`Screen.Chat` 的参数一个不动
- ❌ 不动状态条、不动 tab2/3/4 的内部
- ❌ 不加依赖、不新增第三方 UI 库
- ❌ 不在列表页加「脚本/标签/Bot 模式」等新入口（Bot Mode 的入口保持现状所在位置）

## 4. 验收（必须给证据）

1. `./gradlew assembleDebug` 通过，贴最后 15 行。
2. 逐条写「怎么确认没变 / 没坏」：
   - 抽屉拉开后的行为、筛选（Threads 等）、长按菜单与原来一致
   - tab1 列表 → 点会话 → 聊天 → 返回 → 回到列表（不是回到抽屉状态错乱）
   - 4 个 tab 互切后返回栈不串；聊天页底部没有导航栏、其余页有
   - 冷启动 + onboarding 完成后落在哪个页面
   - 分页加载更多 / 空列表 / 加载失败重试 三个状态各截一句说明
3. 交付说明列出：新文件、改动文件、新增 route、新增 strings key、`testTag` 清单、
   **`SessionDrawerContent` 抽取前后的参数签名对比**（说明哪些参数变成了 body 的入参）。
4. 单测：云端 Robolectric 拉不到 maven 会大面积失败（块2/块3 实测 97~99 项，全是这个原因），
   照跑一次并说明失败项与本次改动无关即可。
