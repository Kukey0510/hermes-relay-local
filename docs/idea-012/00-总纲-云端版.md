```

├─ tab1 对话   落地页 = 全部会话列表；右上角「＋」新建；点会话 → 聊天页（二级）
```

## 4. 现状代码事实（已核实，别重新调研）

| 项 | 值 |
|---|---|
| `ui/RelayApp.kt` | 4102 行；`RelayApp()` 一个 composable 约 3328 行 |
| `ui/screens/ChatScreen.kt` | 5879 行；`ChatScreen()` 约 4432 行 |
| `ui/components/SessionDrawer.kt` | 2176 行；`SessionDrawerContent` 参数 30+ 个，`ChatScreen` 调用处传了 59 个实参 |
| `ui/screens/BridgeScreen.kt` | 982 行 |
| `ui/screens/SettingsScreen.kt` | 1628 行，分 `settings_hermes` / `settings_power_tools` / `App` 三组 |
| `ui/` 总量 | 约 106,892 行 Kotlin |
| NavHost 路由 | 31 条，全部注册在 `RelayApp.kt` |
| `startDestination` | `if (onboardingCompleted) Screen.Chat.route else Screen.Onboarding.route` |
| 依赖 | `navigation-compose 2.10.2` + `compose-material3` 已有，**不需要加任何依赖** |
| `testTag` | 全项目仅 59 处，本次顺手补 |
| 底部现状 | 没有 NavigationBar，底部是 `RelayStatusStrip`（连接徽章 + 路由 + 模型 + 配置名），点一下进 Connections |

**必须知道的雷：**

1. `Screen.Manage` 背后是 `DashboardManagementScreen`（5128 行），`Terminal` / `Bridge` / `BotMode` 只能从这里进 —— 这就是用户抱怨「杀后台要一级级点」的根因。
2. `SessionDrawerContent` 参数爆炸，tab1 复用要**抽 body**，不许复制 2176 行。
3. `Screen.Chat.route` 是**路由模板**（带 `{openAgentSheet}` 等占位），跳转必须用 `Screen.Chat.route(...)` 构造 URI，不能直接 navigate 模板串。
4. 监管模式（supervised）会在每个路由入口用 `isSupervisedRouteContentAllowed(...)` 拦，新页面照抄这个判断。
5. `RelayApp.kt` 里 `when (event)` 处理返回键/深链，搬 NavHost 时这层不能丢。
6. 六套语言包（zh-Hans / de / es / ja / pt-BR），新增 string 只补 `values` + `values-b+zh+Hans`，其余回落。

## 5. 硬约束（违反即打回）

1. **只改** `app/src/main/kotlin/com/hermesandroid/relay/ui/` 与 `app/src/main/res/` 里的 strings。
2. **`network/`、`accessibility/`、`bridge/`、`data/` 一行不碰。**
3. `viewmodel/` 只在「已有字段要暴露给新页面」时改，不改内部逻辑。
4. **不加第三方依赖。**
5. 文案全走 `strings.xml`，Kotlin 里**不许硬编码中英文**。
6. 关键交互元素补 `Modifier.testTag("...")`，点分小写命名，跟 screen 走不跟文案走：`tab.chat` / `tab.scripts` / `chat.newSession` / `bridge.screenshot`。
7. **不改任何现有路由字符串**（深链、二维码、通知跳转依赖它）。
8. 每批交付**完整文件**，不要 diff 片段。
9. 不碰 `plugin/`（服务端 Python 在线上跑）。
10. **先落盘再验证**：先把改动写进文件，再编译跑测试；不要先输出长篇设计方案占上下文。
11. 有歧义就问，**不要自己加功能**（用户明确说过「不动功能」）。
