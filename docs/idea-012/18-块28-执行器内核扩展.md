# 块28 · 执行器内核扩展（swipe / tapIfText / if_page / loop）

> 2026-11-14 立。用户口径：「要补的执行器、内核、底层的东西都补一下」。
> 执行方：Codex（云端能编译、能反复试错）。验收：CI `unit-tests` + 小赫读 diff。
> 基线：`main` 上的 `4efbe1d`（含块24 outbox、块25 标签）。

## 背景：为什么必须补

现在 DSL 只有 5 个 op：`tap / tapText / wait / probe / read`（`script/runtime/ScriptStep.kt`）。
三款游戏的日常都跑不起来，缺的不是判据而是控制流：

| 缺的能力 | 卡住什么 |
|---|---|
| 滑动 | 演习列表/关卡列表/基建列表要滚动才能选到目标 |
| 条件点击 | 公告、体力不足、网络重试这些弹窗只能盲点，点空就浪费一步 |
| 判页分支 | 「在主城才点出击，不在就先返回」表达不了 |
| 循环 | 演习 N 轮、探索 4 类、派遣多轮、周本「行动 ×N」全都写不成 |

## 要新增的 4 个 op（JSON 形态定死）

```json
{"op": "swipe",      "from_x": 1200, "from_y": 900, "to_x": 1200, "to_y": 300, "duration_ms": 400}
{"op": "tapIfText",  "text": "确定", "optional": true}
{"op": "if_page",    "expect": "home", "then": [ ...步骤... ], "else": [ ...步骤... ]}
{"op": "loop",       "times": 5, "max_total_ms": 600000, "until": "result", "steps": [ ...步骤... ]}
```

字段语义：

- **swipe**：`duration_ms` 缺省 400，钳到 50~2000；坐标超屏按当前屏宽高钳（不报错，钳完照滑）。
- **tapIfText**：目标文案**不存在就跳过并记 success**（这是它和 `tapText` 的唯一区别）；
  `optional` 缺省 true，写 false 时找不到算失败。找不到时的日志 message 固定为 `absent:<文案>`。
- **if_page**：`then` / `else` 都是步骤数组，缺省空数组。**只允许一层**，嵌套 `if_page` 直接判
  `invalid_script`（不要递归，先别把复杂度引进来）。判定用现有 `access.probe(expect, timeout)`。
- **loop**：`times` 必填 ≥1（上限 100）；`until` 可选，给了就在每轮结束后 `probe(until, 1s)`，命中即提前结束；
  **硬闸**：`times` 与 `max_total_ms`（缺省 600000）任一触发就停，停止原因写进日志
  （`loop_stop:times` / `loop_stop:max_total_ms` / `loop_stop:until`）。
  子步骤里出现 `loop` 也算嵌套 → `invalid_script`。

## 硬约束

1. **向后兼容**：现有 5 个 op 的 JSON 与语义一个字节都不许变；老脚本不加字段照跑。
2. **JSON 键名**：沿用现有下划线风格（`timeout_ms` / `retries`），新键不许用驼峰。
3. **`retries` 与 `timeout_ms` 对 4 个新 op 同样生效**（继承现有 `ScriptStep` 的三个公共字段）。
4. **`id` 字段照旧可选**，`if_page` 的 then/else 子步骤、`loop` 的子步骤各自可以带 id。
5. 只许改：
   - `app/src/main/kotlin/com/hermesandroid/relay/script/runtime/ScriptStep.kt`（加 sealed 子类 + 序列化分支）
   - `app/src/main/kotlin/com/hermesandroid/relay/script/runtime/ScriptRunner.kt`（`ScriptAccess` 接口加 `swipe` 默认实现 + execute/perform 分派）
   - `app/src/main/kotlin/com/hermesandroid/relay/script/runtime/ScriptGuard.kt`（若需要新 op 的包名检查）
   - `app/src/main/kotlin/com/hermesandroid/relay/script/runtime/ScriptRuntime.kt`（`AndroidAccess` 实现 swipe，
     已有现成方法：`HermesAccessibilityService.instance.actionExecutor.swipe(startX, startY, endX, endY, durationMs)`）
   - `app/src/test/kotlin/com/hermesandroid/relay/script/runtime/**`（测试）
6. **不许碰**：`accessibility/`、`network/`、`ui/`、`bridge/`、`app/src/main/assets/`、`gradle/`。
7. **测试里不许 import `android.*` 或 `org.robolectric.*`**：执行器逻辑走纯 JVM（`ScriptAccess` 用假实现）。

## 测试要求（每个 op 至少两条）

- swipe：正常一次；`duration_ms` 越界被钳；坐标越界被钳。
- tapIfText：文案存在 → 点了；文案不存在 → 跳过且 success=true；`optional=false` 且不存在 → success=false。
- if_page：命中走 then、不命中走 else；`then`/`else` 里的失败会让整步失败；嵌套 `if_page` 判 `invalid_script`。
- loop：`times=3` 跑满 3 轮；`until` 在第 2 轮命中后提前停；`max_total_ms` 触发后停且不抛异常；
  `times=0` / `times=101` 判 `invalid_script`。
- 日志：每个新 op 的 `op` 名与上面 JSON 里的字符串一致（`swipe` / `tapIfText` / `if_page` / `loop`），
  停止原因按 `loop_stop:*` 写。
