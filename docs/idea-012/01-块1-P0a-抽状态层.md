# 块 1 · P0-a 抽状态层（零 UI 变化）

先读同目录 `00-总纲-云端版.md`（环境、硬约束、代码事实都在那里）。本文件只讲这一块。

**本批目标**：把 `RelayApp()` 里「收集长期状态」的那一坨逻辑搬到一个独立文件，让 `RelayApp()` 变薄。**不产生任何视觉变化，不动路由，不动 ChatScreen。**

---

## 1. 为什么要先做这块

`RelayApp()` 现在是 717 行到 4045 行（约 3328 行），里面同时塞着：启动自检、连接状态、监管策略、Scaffold、31 个路由注册、抽屉宿主。

后面三块（底部导航 / tab1 列表 / tab3 bridge）都要改这个函数。不先把它拆开，每一块都会在 3000 行的大函数里互相打架、冲突、改一处崩三处。

---

## 2. 本批只做这些

1. 新建 `app/src/main/kotlin/com/hermesandroid/relay/ui/state/AppRuntimeState.kt`：
   - 把 `RelayApp()` 里**纯状态收集**的部分搬进去，包成一个 `@Composable fun rememberAppRuntimeState(...): AppRuntimeState`（名字可按项目习惯微调，但要在交付说明里写清）。
   - 典型内容：启动自检结果、连接/会话状态、监管（supervised）策略与当前路由允许判定所依赖的状态、以及那些只被 UI 读取的 `rememberXxx` / `collectAsStateWithLifecycle` 组合。
   - 判据：**只搬「读数据 + 组合状态」的代码，不搬「画界面」的代码。**
2. `RelayApp()` 里改成调用 `rememberAppRuntimeState(...)`，用返回的结构体/数据类拿这些值；函数体其它行为一律照旧。
3. 顺手给 `AppRuntimeState` 加中文注释，写清每个字段是给谁用的（后面几块的人要读它）。

## 3. 本批明确不要做

- ❌ 不改任何界面外观、不改 Scaffold 结构、不加底部导航。
- ❌ 不动 `ChatScreen.kt`、`SessionDrawer.kt`、`BridgeScreen.kt`、`SettingsScreen.kt`。
- ❌ 不动 NavHost 的路由注册顺序与 `startDestination`。
- ❌ 不重命名既有 `Screen` 对象、不改任何 `route` 字符串。
- ❌ 不「顺手优化」`ChatScreen` 里那 10+ 个滚动跟随 / IME 判定函数（`shouldFollowImeAfterInsetChange`、`requiredBottomFollowScroll` 等），它们原样保留。

---

## 4. 验收（必须全过，缺一条算没做完）

1. `RelayApp()` 函数体行数**明显下降**（目标 ≤ 2200 行；这一块只搬状态，不指望到 300，300 是块 2 的目标）。交付里报出「改前 / 改后」的实际行数。
2. `./gradlew assembleDebug` 通过，贴输出的最后 15 行。
3. 单元测试全绿（先查明真实 task 名），贴 `BUILD SUCCESSFUL` 与测试数量。
4. **功能零变化**：启动流程、配对、聊天、31 条路由跳转、返回键/深链处理、监管模式拦截，行为与改前一致。你在交付说明里逐条写「怎么确认没变」。
5. 交付说明里列出：新建文件、改动文件、`RelayApp()` 改前/改后行数、你搬走了哪几组状态。

---

## 5. 提交

- 提交到 `feat/ui-redesign`（当前分支），commit message 中文，例如：`refactor(ui): 抽出 AppRuntimeState，RelayApp 状态收集外移（零 UI 变化）`。
- 一个提交装完这一块，别夹带其他改动。
