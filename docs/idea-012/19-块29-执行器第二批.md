## 一、新增 op（JSON 形态定死）

```json
{"op": "launch",       "package": "com.bilibili.azurlane", "wait_ms": 8000}
{"op": "back"}
{"op": "wait_stable",  "timeout_ms": 10000, "frames": 3, "interval_ms": 250, "tolerance": 2}
{"op": "snapshot",     "tag": "pre_battle"}
```

### launch

- `package` 可省，省略时取 `RuntimeScript.targetPackages.first()`；两者都没有 → `StepOutcome(false, "launch_no_package", "invalid_script")`。
- `wait_ms` 缺省 0，`coerceIn(0, 45_000)`（脚本可传 45 秒，超出截到 45 秒），用 `access.waitMs` 等。**不要**在这里做判页，判页交给后面的 `probe`。
- 实现：`ScriptAccess.launchApp(pkg: String): Boolean`。
  `AndroidAccess` 里用 `context.packageManager.getLaunchIntentForPackage(pkg)` + `addFlags(FLAG_ACTIVITY_NEW_TASK)` + `startActivity`。
  拿不到 intent → 返回 false → `StepOutcome(false, "launch_failed")`。

### back

- `ScriptAccess.back(): Boolean`；`AndroidAccess` 用
  `service.performGlobalAction(AccessibilityService.GLOBAL_ACTION_BACK)`。
- 没有参数。返回 false → `StepOutcome(false, "back_failed")`。
- 注意（写进代码注释）：在根页面按 back 会退到桌面，所以脚本里 `back` 之后必须跟 `probe`。

### wait_stable

- 语义：连续 `frames` 次采样之间画面几乎不变，才算稳定。
- 参数钳制：`frames` → 2..6（缺省 3）；`interval_ms` → 100..1000（缺省 250）；
  `timeout_ms` → 500..30_000（缺省 10_000）；`tolerance` → 0..32（缺省 2）。
- 算法（**放在 runner 里，纯 JVM 可测**）：
  1. `previous = access.frameSample()`
  2. 循环：`delay(interval)` → `current = access.frameSample()`
     - 任一为 null → `StepOutcome(false, "capture_failed")`
     - `meanAbsDiff(previous, current) <= tolerance` → `stable++`，否则 `stable = 0`
     - `stable >= frames - 1` → `StepOutcome(true, "stable_after=<elapsed>ms")`
     - 超过 `timeout_ms` → `StepOutcome(false, "not_stable")`
     - `previous = current`
- `ScriptAccess.frameSample(): IntArray?`：返回**抽样后**的像素通道值（每 32 个像素取 1 个，RGB 三通道展开）。
  纯 JVM 测试用假实现造数组；`meanAbsDiff` 写成 `internal fun` 便于单测。
- 两种采样长度不同 → 视为不稳定，不崩。

### snapshot

- `ScriptAccess.saveSnapshot(tag: String): Boolean`；`AndroidAccess` 用
  `screenCapture.captureLocalFrame()` → `FrameArchive.save(context, image, tag)`。
- `tag` 缺省 `manual`，只允许 `[a-zA-Z0-9_-]{1,32}`，超范围替换成 `_`。
- 失败 → `StepOutcome(false, "capture_failed")`。

## 二、变量（不改 op 数量，改语义）

- 脚本 JSON 顶层新增可选 `"vars": { "名": 数字或字符串 }`。
- `read` 新增可选 `as`：`{"op":"read","field":"jjc_times","as":"times"}`，缺省 `as = field`。
  读到的值先**提取第一个数字串**（`"5/5"` → 5，`"12"` → 12，无数字 → 不写入变量），再存进变量表。
- `loop` 新增可选 `"times_from": "<变量名>"`：给了就用变量值（取第一个数字）覆盖 `times`；
  变量不存在或没有数字 → 回落到 `times`，日志写 `times_fallback`。**`times` 仍是 Int**，不改类型，保持老脚本兼容。
- `loop.until`、`if_page.expect`、`tapText.text`、`tapIfText.text` 也支持 `${var}` 替换（统一在 perform 入口做一次替换）。
- 变量表生命周期 = 一次 `run()`，不跨次。

## 三、失败兜底 on_fail

- 脚本顶层可选 `"on_fail": [步骤...]`。
- 触发条件：主步骤序列以 `success=false` 结束时（`step_failed` / `invalid_script` / `launch_failed` / `not_stable` 全都算）。
  `run_in_progress` **不触发**。
- 执行规则：最多 10 步、总时长 ≤ 60 秒；只记日志**不改**最终 `errorCode` 与 `success`；
  `on_fail` 内部的失败不重试、不递归触发 on_fail。
- 日志里 on_fail 的步骤 `stepIndex` 用 `-1`，`op` 前缀 `on_fail:`（如 `on_fail:tapText`），便于区分。
