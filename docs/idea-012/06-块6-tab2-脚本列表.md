# 块 6 · tab2 脚本列表 + 详情（只展示，不执行）

先读 `00-总纲-云端版.md`。基线：块1-5 已合并，tab2 当前是占位页（一句「游戏脚本清单即将上线」）。

---

## 1. 本批目标

tab2 变成**手机侧游戏脚本清单**：卡片列表 → 点开看详情。**只展示，不执行**（用户原话：「只做展示，详情之类的，后面有需要再补跑」）。

## 2. 数据从哪来（本批就这么定，别自己发明网络接口）

服务器推送通道**还没做**，也不在本批范围内。做法：

1. 新建 `app/src/main/assets/scripts.json`，内置 3~5 条示例数据（覆盖不同游戏：盲盒派对 / 交错战线 / 碧蓝航线，字段见下）。
2. 新建一个薄数据层 `ui/scripts/ScriptCatalog.kt`：
   - `data class ScriptEntry(id, name, game, tag, updatedAt, description, steps: List<String>, sourceNote)`
   - `object ScriptCatalog { fun load(context): List<ScriptEntry> }` 读 assets 的 JSON，解析失败返回空表 + 不崩
   - **将来接服务器只替换这一层**，界面不用改；在 README/注释里写清这个替换点
3. 不新增第三方 JSON 库：项目里已有 kotlinx.serialization 或 org.json 就用现成的（先用 `grep` 确认，别猜）。

## 3. 界面

4. tab2 页（`Screen.Scripts` 的占位换成真列表）：
   - 顶部标题 + 右上角刷新图标（重新读 assets，`testTag="scripts.refresh"`）
   - 卡片列表：每张卡显示 名称 / 游戏 / 标签 / 更新时间
   - 空列表要有空态文案；解析失败要有错误态 + 重试
   - 点卡片 → 详情页 `Screen.ScriptDetail(scriptId)`（新增路由，`scriptId` 走 path 或 query 参数，与项目现有写法一致）
   - `testTag`：`scripts.list` / `scripts.item.<id>` / `scripts.detail`
5. 详情页：名称、游戏、标签、更新时间、说明、步骤清单（有序号），底部一行小字说明「本版本只展示，不执行」。

## 4. 明确不要做

- ❌ 不执行任何脚本、不接线 bridge、不发网络请求
- ❌ 不做服务器推送通道、不做 tag 编辑、不做收藏/排序
- ❌ 不改 tab1/tab3/tab4
- ❌ 不加第三方依赖
- ❌ 不硬编码中英文（示例数据的名称可以放 assets JSON 里，界面文案走 strings.xml）

## 5. 验收

1. `./gradlew assembleDebug` 通过，贴最后 15 行。
2. 逐条写：
   - tab2 首屏显示几条卡片、各是什么
   - 点进详情、返回键回到列表
   - 把 assets 里的 JSON 故意改坏 → 走错误态而不是崩（贴一次实测）
   - 空数组 → 空态文案
   - 切走再切回 tab2 状态是否保留
3. 交付说明：新增文件、新增 route、新增 strings key、`testTag` 清单、**将来接服务器要改哪一行**。
