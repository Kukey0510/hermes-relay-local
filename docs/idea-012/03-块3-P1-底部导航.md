# 块 3 · P1 底部 4 tab + 设置页落位（第一批真视觉变化，要出包）

先读同目录 `00-总纲-云端版.md`（环境、硬约束、代码事实）和 `02-块2-P0b-拆骨架.md`（块2 已完成）。
本文件只讲这一块。

**现状基线**：`feat/ui-redesign` 的 HEAD 上，块1（状态层）+ 块2（骨架）都已合并。
`ui/AppScaffold.kt` 3507 行承载 `Scaffold` + `RelayStatusStrip` + `NavHost` + 全部路由；
`RelayApp.kt` 795 行，`RelayApp()` 只有 3 行（收集状态 + 调 `AppScaffold()`）。

---

## 1. 本批目标

底部出现常驻导航栏，4 个 tab：**对话 / 脚本 / Bridge / 设置**。
本批**只做导航骨架 + 4 个目的地接线**，tab 页内部内容不动（tab2/3 是占位）。

## 2. 必须做

1. `AppScaffold` 的 `Scaffold.bottomBar` 从「只有 `RelayStatusStrip`」改成
   **`Column { RelayStatusStrip(); NavigationBar { 4 个 item } }`**。
   - `RelayStatusStrip` **不许删、不许改内部**：它的新去处（tab3 顶部）是块5 的事，
     本批先留在底部、压在导航栏上面。
   - 用 `material3` 的 `NavigationBar` / `NavigationBarItem`，依赖已有，**不许加依赖**。
2. 4 个 tab 目的地：
   | tab | 目的地 | 本批状态 |
   |---|---|---|
   | 对话 | `Screen.Chat`（`Screen.Chat.route(openAgentSheet = false)`） | 现有聊天页，内容不动 |
   | 脚本 | **新增** `Screen.Scripts` | 占位页：一句「游戏脚本清单即将上线」，纯 `strings.xml` 文案 |
   | Bridge | `Screen.Bridge` | 现有页面，内容不动 |
   | 设置 | `Screen.Settings` | 现有 `SettingsScreen`，内容不动 |
3. 新增 `Screen.Scripts` 时：route 字符串自己起一个不与现有冲突的名字（如 `"scripts"`），
   **只新增，不许改任何现有 route 字符串**，`Screen` 对象其余部分一行不动。
4. tab 切换行为：标准 4 tab 语义 —— 点 tab 用 `navigate(route) { popUpTo(起跑目的地) { saveState = true }; launchSingleTop = true; restoreState = true }`，
   **保证切换 tab 不叠栈、返回键不退出 App、切回来页面状态还在**。
5. 导航栏选中态：按当前 `currentBackStackEntry` 的 route 判断归属，子页面（如 Settings 下的子路由、
   Manage 下的 Terminal/Bridge 子页）要能映射回它的父 tab，别出现「进了子页 4 个 tab 全灭」。
6. 每个 tab item 补 `testTag`：`tab.chat` / `tab.scripts` / `tab.bridge` / `tab.settings`。
7. 文案走 `strings.xml`：新增 `tab_chat` / `tab_scripts` / `tab_bridge` / `tab_settings`
   与占位页文案，**只补 `values/` 与 `values-b+zh+Hans/`**，其余语言回落。Kotlin 里不许硬编码中英文。

## 3. 明确不要做

- ❌ 不动 `ChatScreen` / `SessionDrawer` / `BridgeScreen` / `SettingsScreen` 的内部内容与布局
- ❌ 不把设置页重排成「分组卡片」（那是块4 之后的事）
- ❌ 不把状态条挪到 tab3 顶部（块5）
- ❌ 不改 `startDestination`（仍是 onboarding ? Chat : Onboarding）
- ❌ 不删任何现有入口：Manage / Terminal / BotMode 的跳转路径一条都不能少
- ❌ 不动监管模式（supervised）的路由拦截判断，新 tab 目的地要按现有方式接入拦截
- ❌ 不改深链 / 二维码 / 通知跳转依赖的 route 字符串

## 4. 验收（必须给证据）

1. `RelayApp()` 仍 ≤ 300 行；`RelayApp.kt` 只允许因可见性/import 有小幅变动。
2. `JAVA_HOME=/opt/jdk17 ANDROID_HOME=/opt/android-sdk ./gradlew assembleDebug` 通过，贴最后 15 行。
3. **逐个 tab 写「怎么确认没变」**：
   - 4 个 tab 点击可达、选中态正确
   - 从 tab4 进设置子页 → 返回键逐层回退、最后回 tab4（不退出 App）
   - 从 tab1 进聊天 → 进 Manage → Terminal → 一路返回不串栈
   - 冷启动落在哪个 tab、onboarding 完成后落到哪
   - 深链进 Bridge/配对页仍然直达且底部导航不遮挡内容
4. 交付说明里列：改了哪些文件、新增的 route 字符串、`strings.xml` 新增 key、`testTag` 清单。
5. 单测：云端 Robolectric 拉 maven 会被网络挡（块2 实测 98~99 项失败全是这个原因），
   **所以本批不要求「单测全绿」**，但必须跑一次并说明失败项是否与本次改动相关；把原始输出尾部贴上来。
