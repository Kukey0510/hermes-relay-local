# 块17 · 执行日志与失败恢复

> 2026-11-13 立。前置：块16 的 `ScriptRunResult` / `ScriptRunLog` 数据结构。
> 用户口径：「日志留三天」「失败推 QQ」「失败尝试叫服务器解决，解决不了报错到会话」。

## 要做的三件事

### 1. 本地运行日志（留 3 天）

- 位置：`filesDir/logs/script-YYYYMMDD.jsonl`，一行一条事件
- 每次运行开始写 `run_start`，每步写 `step`（op / 结果 / 耗时），结束写 `run_end`
- 保留策略：**启动时清理 3 天前的文件**（按文件名日期，不按 mtime）
- App 内能看到：脚本详情页「最近运行」列表（读当天文件尾部 50 行即可）

### 2. 失败上报（`POST {base}/script-events`）

- 契约见 `docs/idea-012/13-scripts-api契约.md` 第 3 节，字段一个都不许多不许少
- 触发点：`level=error` 的停手、`guard_*` 拦截、运行结束
- 上报失败：**只记本地日志，不重试超过一次**，绝不能让上报把脚本运行卡住
- 上报是异步的，不许阻塞步骤执行

### 3. 未完成运行（pending）

- 运行开始写 `filesDir/scripts/pending_run.json`（scriptId、runId、起始 step）
- 正常结束（成功或失败停手）删除该文件
- App 进程被杀导致残留：下次进 tab2 顶部提示一行「上次有未完成的运行 · 查看日志」，**不自动重跑**
- 用户点开能看到停在哪个 step

## 不许碰

- 块16 的 `ScriptRunner` 内部步骤语义（只在它产出的 result 上工作）
- `accessibility/`、`bridge/`、`network/relay/`
- 服务器侧推送逻辑（小赫实现）

## 验收

1. `./gradlew :app:assembleSideloadDebug --no-daemon` BUILD SUCCESSFUL
2. `./gradlew :app:testSideloadDebugUnitTest --no-daemon` 不新增失败
3. 单测至少覆盖：3 天前文件被清理、当天文件保留、pending 写读删、上报失败不抛该影响主流程
4. 报告写清：日志文件名规则、清理判定依据、上报调用点、pending 文件路径
