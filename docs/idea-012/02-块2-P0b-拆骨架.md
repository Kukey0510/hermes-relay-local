# 块 2 · P0-b 拆骨架（AppScaffold + NavHost 搬迁）

先读同目录 `00-总纲-云端版.md`（环境、硬约束、代码事实都在那儿）和 `01-块1-P0a-抽状态层.md`（块1 已完成，看懂它抽了什么）。
本文件只讲这一块。

**本批目标**：把 `RelayApp()` 里「Scaffold + NavHost + 31 条路由注册」整体搬到新文件，让 `RelayApp()` 落到 300 行以内。
**仍然不产生任何视觉变化。**

---

## 1. 现状

- `ui/RelayApp.kt` 4102 行。块1 已经把「状态收集」抽成了 `ui/state/AppRuntimeState.kt`，`RelayApp()` 现在通过它拿状态。
- 剩下的主体是：`Scaffold`（bottomBar 是 `RelayStatusStrip`）+ `NavHost`（31 条 `composable(...)`）+ `when (event)` 的返回键/深链处理 + 抽屉宿主。
- `startDestination` 仍是 `if (onboardingCompleted) Screen.Chat.route else Screen.Onboarding.route`。

## 2. 本批只做这些

1. 新建 `app/src/main/kotlin/com/hermesandroid/relay/ui/AppScaffold.kt`：
   - 承载 `Scaffold`（本批 bottomBar 仍然是原来的 `RelayStatusStrip`，**不要**换成 NavigationBar）
   - 承载 `NavHost` 与全部 31 条 `composable(...)` 注册，路由常量继续引用 `Screen`（**不许改任何 route 字符串**）
   - 承载 `when (event)` 的返回键 / 深链处理
2. `RelayApp()` 只保留：拿 `AppRuntimeState` → 调 `AppScaffold(...)`。
3. 31 条路由的注册顺序、`arguments` 定义、`isSupervisedRouteContentAllowed(...)` 判断，**逐条原样搬**，一条都不能漏。

## 3. 本批明确不要做

- ❌ 不加底部导航栏（那是块 3）。
- ❌ 不改 `ChatScreen` / `SessionDrawer` / `BridgeScreen` / `SettingsScreen`。
- ❌ 不改 `startDestination` 的行为。
- ❌ 不重命名 `Screen` 对象、不动 route 字符串。
- ❌ 不顺手优化任何滚动/IME 判定函数。

## 4. 验收

1. `RelayApp()` 函数体 **≤ 300 行**，交付里报「改前 / 改后」行数。
2. `./gradlew assembleDebug` 通过，贴输出最后 15 行。
3. 单元测试全绿（贴 `BUILD SUCCESSFUL` 与测试数量）。
4. **功能零变化**：31 条路由逐条可跳、返回键行为、深链、监管模式拦截、配对、聊天——逐项写「怎么确认没变」。
5. 交付说明里列：新文件、改动文件、`RelayApp()` 行数、路由条数核对（搬过去几条 vs 原来几条，必须 31 = 31）。

## 5. 提交

提交到 `feat/ui-redesign`，commit message 中文，例如：
`refactor(ui): 抽出 AppScaffold 承载 Scaffold+NavHost，RelayApp 降到 N 行（零视觉变化）`
一个提交装完这一块，别夹带别的改动。
