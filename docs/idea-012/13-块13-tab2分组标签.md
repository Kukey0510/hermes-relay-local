# 块13 · tab2 脚本列表：分组筛选 + 自定义 tag

> 2026-11-13 用户报，登记待做。

## 用户原话

> tab2 也增加分组筛选器，允许自己修改 tag
> （hermes 在下一次推新脚本的时候，同步 tag）

## 现状（代码核实）

- 屏幕：`ui/screens/ScriptsScreen.kt`
- 数据：`app/src/main/assets/scripts.json`，4 条内置示例，字段：
  `id / name / game / tag / updatedAt / description / steps / sourceNote`
- `tag` 现在是**单值字符串**（如「日常」「养成」），只展示、不可改
- 没有任何筛选器，就是一列卡片

## 要做的改动

1. **分组筛选器**（照 tab1 的做法，别另起一套 UI）：
   - 顶部一排横向 chips：「全部」+ 各 tag
   - 多选按「或」，与搜索（如果有）按「且」
   - 分组建议按 **tag**（现在是 game + tag 两个维度，tag 更贴「用途」）
2. **tag 可自己改**：
   - 长按/详情里编辑，可多选已有 tag、也能新建
   - 存本地 DataStore（`{ scriptId: [tag...] }`），不写回 assets
3. **推送时同步 tag**（Hermes 侧）：
   - 下次我推新脚本时，`scripts.json` 里带默认 tag
   - 冲突以服务器为准；但服务器那份没变而手机上改过，则把手机上的改动回写上去（见下节）

## 设计要点（2026-11-13 用户定稿）

- 复用 tab1 的 `SessionOrganizationStore` 模式（DataStore + JSON 映射），
  但**不要共用一个 store**，脚本 tag 和会话 tag 是两套数据
- `tag` 字段现在单值，改多值要兼容旧 JSON（单值自动包成列表）
- 筛选状态不持久化（和 tab1 一致）

### tag 冲突策略（用户明确）

1. **以服务器同步下来的为准** —— 推送值优先
2. **服务器脚本没变动、但手机上的 tag 改了 → 要把服务器那份也更新**（本地改动要回写上行）
3. **一个脚本可以有多个 tag**
4. **分组由用户自己分** —— 我们只管把 tag 做成可编辑 + 可筛选，不预设分组规则

### 由此带来的实现要求

- 本地改 tag 后必须能**回写到服务器那份**（`scripts.json` 或未来的推送源），
  不能只在手机本地飘着
- 回写通道建议走已有 relay bridge（不走新协议），或者退一步：
  app 记「待同步」标记，由 Hermes 侧读取后落到源数据
- 推送时的合并规则：服务器有更新 → 覆盖 tag；服务器无更新 → 保留/回写本地 tag
